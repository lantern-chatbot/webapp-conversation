# 会話ログをGoogleスプレッドシートに保存

このWebアプリから送った質問とDifyの回答を、1往復1行で保存します。Next.jsがストリームを転送しながら回答を組み立て、応答終了後にGoogle Apps Script（GAS）へ送信します。Difyの既存ログ・別の入口からの質問は取り込みません。保存時にキーワードで分類し、スプシのメニューから期間別に集計できます。

## 検証用の初期設定

1. アクセスを担当者に限定した検証用スプレッドシートを作成し、「拡張機能 → Apps Script」を開きます。
2. このフォルダの `Core.js`、`Code.js`、`Analysis.js`、`AnalysisUI.js`、`Presentation.js`、`Details.js` を、それぞれ同名の `.gs` ファイルとしてコピーします。既存の空のCode.gsは置き換えます。6ファイルを同じGASプロジェクトに置きます。
3. プロジェクト設定でマニフェストを表示し、`appsscript.json` を反映します。高度なGoogle Sheetsサービス（v4）を有効にします。標準Google Cloudプロジェクトを使う場合は、そのプロジェクトのSheets APIも有効にします。
4. スクリプトプロパティを設定します。

   | プロパティ | 値 |
   | --- | --- |
   | `SPREADSHEET_ID` | 保存先のスプレッドシートID |
   | `CHAT_LOG_SECRET` | ランダム生成した32文字以上の共有秘密 |
   | `CHAT_LOG_ENVIRONMENT` | 検証は `test`、本番は `production` |

5. `setupChatLog` を実行し、Googleの権限確認を行います。「会話ログ」「分類ルール」「集計」「その他」「要確認」と非表示の「集計データ」が作成されます。「会話ログ → 集計を更新」で画面を描画します。再実行は既存の会話やルールを消しません。同名シートが別用途の場合は停止します。専用のスプレッドシートを使ってください。
6. ウェブアプリとして新しいデプロイを作成します。実行者は所有者、アクセスできるユーザーは「全員」です。スプレッドシート自体は公開しません。組織のWorkspaceポリシーが外部アクセスを禁止している場合は、ここで止めて認証方式を再設計してください。
7. `/exec` で終わるデプロイURLを控え、Next.jsのPreview環境に以下を設定して再デプロイします。

   ```dotenv
   CHAT_LOG_MODE=test
   CHAT_LOG_URL=https://script.google.com/macros/s/DEPLOYMENT_ID/exec
   CHAT_LOG_SECRET=同じ共有秘密
   ```

秘密は環境変数とScript Propertiesにだけ保存します。ソース、URLのクエリ、Issue、ログには記載しません。GASは秘密・環境・レコードを検証してからスプレッドシートを開きます。公開WebアプリのエンドポイントにはGoogleの実行回数制限が適用されます。

## 本番への反映

検証後、本番用の別スプレッドシート・GASプロジェクト・共有秘密を準備し、同じ手順で設定します。GAS側は `production`、VercelのProduction環境は `CHAT_LOG_MODE=production` とします。`VERCEL_ENV=production` と一致しない設定は送信を無効にし、サーバーログに設定エラーを出します。Previewは検証用の設定のままにします。

GASソース変更後は、ウェブアプリのデプロイを新しいバージョンに更新します。ソース保存だけでは既存の `/exec` に反映されません。この実装はVercelのProduction判定を使います。他のホスティングを使う場合は環境判定を別途設計してください。

## 保存される情報

- 日時（質問受付時刻、Asia/Tokyo）、質問、回答、生成状態、会話・メッセージ・リクエスト・アプリのID。
- 担当者が記入する「修正カテゴリ」「担当者評価」「メモ」。その他の列やヘッダーの削除・並べ替えはしません。
- 回答にはカード表示用トークンも原文のまま保存します。回答の正しさは担当者が評価します。「完了」は生成処理の完了を示します。
- 回答は最大120,000文字を40,000文字ずつ3セルに分割します。全文は行を選び「会話ログ → 選択行の詳細を開く」で表示できます（C・R・S列を結合）。上限超過や不正なストリームでは「捕捉状態」を記録し、「完了」にしません。ブラウザへ転送する回答は変更しません。
- 質問・回答が `=` で始まっていても文字列として保存し、数式として実行しません。

同じメッセージID（未取得時はリクエストID）の再送は追加しません。担当者が編集したメモも維持します。Cookie、Dify APIキー、ワークフローの内部入力は保存しません。質問・回答自体に個人情報が含まれる可能性があるため、保存先の閲覧権限と保存期間を運用時に決めます。

## 確認

### 分類・集計の使い方

1. シートを再読み込みすると「会話ログ」メニューが表示されます。
2. 「分類ルール」でカテゴリ・キーワード・優先順位を編集します。「含む語」はカンマ・読点・改行区切りのいずれかに部分一致、「除外語」はいずれにも一致しない質問が対象です。有効なルールの優先順位が小さいものを優先し、同順位では上の行を優先します。全角・半角・英字の大文字小文字は正規化します。初期ルールは料金、採用、導入相談、サービス、会社情報、問い合わせで、一致しなければ「その他」です。
3. 誤分類は「会話ログ」のE列「修正カテゴリ」で修正できます。F列「集計カテゴリ」は修正を優先します。担当者評価・メモはH・I列です。
4. 「集計」のB2に開始日、B3に終了日を `YYYY-MM-DD` 形式で入力します。空欄なら制限しません。メニュー「集計を更新」で日本時間の両端の日付を含めて再集計します。
5. 「集計」は上段に質問数・会話数・要確認件数・その他の割合、中段にカテゴリ別・日別グラフ、下段にカテゴリの件数・割合、生成状態、要確認の理由、頻出質問上位10件と割合、最近の要確認質問5件を表示します。要確認の理由は重複して数えます。本文は12pt、主要数値は34ptで表示し、グラフには件数ラベルを付けます。会話ID不明件数は会話数の補足に表示します。カテゴリが9種類以上あるときはグラフの9位以下をまとめます。全質問の頻度は非表示の「集計データ」シートで確認できます。
6. 「その他」「要確認」は日時・カテゴリ・質問・回答の抜粋・確認状況・原本の6列です。行を選んで「会話ログ → 選択行の詳細を開く」で全文を読みます。原本リンクは集計時点の元行へ移動します。元ログを並べ替えた場合は再集計してください。詳細メニューは記録キーで元行を再検索します。手動修正・評価・メモは元の「会話ログ」の黄色い欄で編集します。
7. 「集計」のB2・B3を除く画面領域、「その他」「要確認」の2行目以降、「集計データ」は更新のたびに置き換わる管理領域です。ここにはメモを書かないでください。一覧のフィルタは更新時に作り直します。原文の20列と手動入力欄は維持します。
8. ルール変更後に過去のログへも適用する場合は「過去ログを再分類」、続けて「集計を更新」を実行します。修正カテゴリ・評価・メモ・原文は変更しません。

新規ログは保存時に自動分類します。集計結果はメニュー実行時点のスナップショットです。ルールが不正・読込不能でも原文の記録は続け、「その他」とルール版 `rules-error` を記録します。ルールを修正して過去ログを再分類してください。分類ルール未作成時は保存だけを行います。

会話数はアプリIDと会話IDの組み合わせを重複除外した数です。会話ID不明のログは質問数には含みますが、会話数には含みません。「要確認」は生成未完了・エラー、または担当者評価が「要改善」「判断不可」の行です。評価「未確認」だけでは抽出しません。同じ質問の頻度は表記を正規化した完全一致で、意味の似た質問の分類や回答の自動採点ではありません。

分析処理は対象ログを読み込むため、件数増加でGASの実行時間・Sheetsの容量制限に近づいたら、期間別ファイルや外部分析基盤への移行を検討します。

### 見た目をローカルで確認

```bash
pnpm preview:sheets
```

生成される `docs/development/sheets-preview.html` をブラウザで開きます。架空の28件から実際の分類・集計・表示モデルを使ったHTMLプレビューです。タブで集計・要確認・その他・会話ログを切り替え、質問の全文も確認できます。Googleへの接続・本番データの読込は行いません。Google Sheetsの画面そのものではなく、チャートはSVGによる再現です。

既存の検証用GASを更新するときも6ファイルを反映し、「初期設定」→「集計を更新」を実行します。B2/B3の期間と原文・手動修正・評価・メモは保持されます。「集計データ」が別用途で存在するときは書込前に停止します。

### 自動テストと実環境の確認

ローカルでは実際のGoogle・Difyに接続せず、以下を実行します。

```bash
pnpm lint
pnpm typecheck
pnpm test
pnpm test:components
pnpm test:e2e
```

E2Eはビルドを含み、テスト用のDifyと保存先で回答のストリーミング・継続会話・保存先障害を確認します。実際のGASの権限、リダイレクト、Googleへの書き込み、Vercelの応答後処理は、上記の実環境設定後に別途確認が必要です。

1. Previewで異なる質問を2回送り、質問・回答が2行、同じ会話IDで保存されること。
2. 検証用GASの共有秘密を一時的に不一致にし、回答表示は成功して保存は失敗すること。検証後は元に戻すこと。
3. 通信失敗・中断のログを「完了」と誤認しないこと。長い回答はC・R・S列を結合して確認すること。
4. 検証用シートへ送信中に本番用シートへ追加されないこと。
5. 初期設定と集計更新を2回実行し、日付入力・原文・評価・メモが残り、グラフが重複せず表示されること。期間内0件でも空状態が表示されること。
6. 一覧のフィルタ・原本リンク・全文表示が動作すること。元ログを並べ替えても詳細メニューは同じ質問を開くこと。実際のGoogle Sheetsでの改行やグラフ位置も確認すること。

## 失敗時と停止

送信は1回5秒、最大3回です。再試行の間隔は250ms・500msです。失敗時はサーバーログの `chat_log_delivery_failed` とリクエストID・コードを確認します。質問・回答・秘密はエラーログに出しません。認証や形式の不一致は再試行しません。

永続キューはありません。サーバーの強制終了、実行時間制限、Googleの長時間障害では保存が欠落する可能性があります。再送回数を超えた記録を自動復旧する仕組みは対象外です。1回の会話応答と後処理がVercelの実行時間内に収まることを検証してください。

停止する場合は `CHAT_LOG_MODE=off` にして再デプロイします。既存のシートの内容は削除しません。Langfuse等の導入判断は #63 で別途扱います。
