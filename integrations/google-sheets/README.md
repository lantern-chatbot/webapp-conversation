# 会話ログをGoogleスプレッドシートに保存

このWebアプリから送った質問とDifyの回答を、1往復1行で保存します。Next.jsがストリームを転送しながら回答を組み立て、応答終了後にGoogle Apps Script（GAS）へ送信します。Difyの既存ログ・別の入口からの質問は取り込みません。分類・集計は後続の #64 で追加します。

## 検証用の初期設定

1. アクセスを担当者に限定した検証用スプレッドシートを作成し、「拡張機能 → Apps Script」を開きます。
2. このフォルダの `Core.js` と `Code.js` を、それぞれ `Core.gs` と `Code.gs` としてコピーします。既存の空のCode.gsは置き換えます。
3. プロジェクト設定でマニフェストを表示し、`appsscript.json` を反映します。高度なGoogle Sheetsサービス（v4）を有効にします。標準Google Cloudプロジェクトを使う場合は、そのプロジェクトのSheets APIも有効にします。
4. スクリプトプロパティを設定します。

   | プロパティ | 値 |
   | --- | --- |
   | `SPREADSHEET_ID` | 保存先のスプレッドシートID |
   | `CHAT_LOG_SECRET` | ランダム生成した32文字以上の共有秘密 |
   | `CHAT_LOG_ENVIRONMENT` | 検証は `test`、本番は `production` |

5. `setupChatLog` を実行し、Googleの権限確認を行います。「会話ログ」が作成されます。再実行は既存データを消しません。既存の列構成が違う場合は停止します。
6. ウェブアプリとして新しいデプロイを作成します。実行者は所有者、アクセスできるユーザーは「全員」です。スプレッドシート自体は公開しません。組織のWorkspaceポリシーが外部アクセスを禁止している場合は、ここで止めて認証方式を再設計してください。
7. `/exec` で終わるデプロイURLを控え、Next.jsのPreview環境に以下を設定して再デプロイします。

   ```dotenv
   CHAT_LOG_MODE=test
   CHAT_LOG_URL=https://script.google.com/macros/s/DEPLOYMENT_ID/exec
   CHAT_LOG_SECRET=同じ共有秘密
   ```

秘密は環境変数とScript Propertiesにだけ保存します。ソース、URLのクエリ、Issue、ログには記載しません。GASは秘密・環境・レコードを検証してからスプレッドシートを開きます。公開WebアプリのエンドポイントにはGoogleの実行回数制限が適用されます。

## 本番への反映

検証後、本番用の別スプレッドシート・GASプロジェクト・共有秘密を準備し、同じ手順で設定します。GAS側は `production`、VercelのProduction環境は `CHAT_LOG_MODE=production` とします。`VERCEL_ENV=production` と一致しない設定は送信を無効にし、サーバーログに設定エラーを出します。Previewは検証用の設定のままにします。

GASソース変更後は、ウェブアプリのデプロイを新しいバージョンに更新します。ソース保存だけでは既存の `/exec` に反映されません。この実装はVercelのProduction判定を使います。他のホスティングを使う場合は環境判定を別途設計してください。

## 保存される情報

- 日時（質問受付時刻、Asia/Tokyo）、質問、回答、生成状態、会話・メッセージ・リクエスト・アプリのID。
- 担当者が記入する「修正カテゴリ」「担当者評価」「メモ」。その他の列やヘッダーの削除・並べ替えはしません。
- 回答にはカード表示用トークンも原文のまま保存します。回答の正しさは担当者が評価します。「完了」は生成処理の完了を示します。
- 回答は最大120,000文字を40,000文字ずつ3セルに分割します。続きを見るには非表示のR・S列を表示します。上限超過や不正なストリームでは「捕捉状態」を記録し、「完了」にしません。ブラウザへ転送する回答は変更しません。
- 質問・回答が `=` で始まっていても文字列として保存し、数式として実行しません。

同じメッセージID（未取得時はリクエストID）の再送は追加しません。担当者が編集したメモも維持します。Cookie、Dify APIキー、ワークフローの内部入力は保存しません。質問・回答自体に個人情報が含まれる可能性があるため、保存先の閲覧権限と保存期間を運用時に決めます。

## 確認

ローカルでは実際のGoogle・Difyに接続せず、以下を実行します。

```bash
pnpm lint
pnpm typecheck
pnpm test
pnpm test:components
pnpm test:e2e
```

E2Eはビルドを含み、テスト用のDifyと保存先で回答のストリーミング・継続会話・保存先障害を確認します。実際のGASの権限、リダイレクト、Googleへの書き込み、Vercelの応答後処理は、上記の実環境設定後に別途確認が必要です。

1. Previewで異なる質問を2回送り、質問・回答が2行、同じ会話IDで保存されること。
2. 検証用GASの共有秘密を一時的に不一致にし、回答表示は成功して保存は失敗すること。検証後は元に戻すこと。
3. 通信失敗・中断のログを「完了」と誤認しないこと。長い回答はC・R・S列を結合して確認すること。
4. 検証用シートへ送信中に本番用シートへ追加されないこと。

## 失敗時と停止

送信は1回5秒、最大3回です。再試行の間隔は250ms・500msです。失敗時はサーバーログの `chat_log_delivery_failed` とリクエストID・コードを確認します。質問・回答・秘密はエラーログに出しません。認証や形式の不一致は再試行しません。

永続キューはありません。サーバーの強制終了、実行時間制限、Googleの長時間障害では保存が欠落する可能性があります。再送回数を超えた記録を自動復旧する仕組みは対象外です。1回の会話応答と後処理がVercelの実行時間内に収まることを検証してください。

停止する場合は `CHAT_LOG_MODE=off` にして再デプロイします。既存のシートの内容は削除しません。Langfuse等の導入判断は #63 で別途扱います。
